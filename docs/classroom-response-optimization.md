# 课中助教回答体验定向优化

验收日期：2026年10月5日。改动沿用当前 Next.js 16.3.8、Prisma、结构化回答和流式聊天。已先阅读实际实现及安装版本的 Next.js Route Handlers、Server/Client Components 指南。

## 1. Root Cause

- **简单问题过度回答、反复出现讲解建议和示例**：`classroom-qa` 提示词要求“输出讲解建议和可直接使用的例句”；`classroomSchema` 要求非空 `teachingSuggestion`；前端 `AnswerDetails` 无条件渲染“教师讲解建议”。三个层面共同强制扩写。
- **资料反复被要求核实**：聊天提示词把参考资料统称“不可信教学数据”，没有区分资料事实的可信度与资料中指令的安全边界；演示分支和输入区也带有例行核实表达。
- **事实和推断混淆**：已有来源规则禁止虚构资料，但没有禁止把数字接近的成绩区间、A/B/C层建立对应关系，也没有要求标记合理推断与证据缺口。
- **来源重复且阅读负担大**：前端按每个检索结果生成文件条目，用命中片段总数作“知识库来源”数量；没有按文件聚合，也没有去除重复片段。原实现虽用了折叠条目，但重复文件、片段级组织和摘录仍使来源区呈现调试风格。
- **联网状态污染普通回答**：系统提示词、网络状态消息及演示分支均要求关闭联网时说明状态；未找到网页时的提示也没有按当前问题的需要限制。
- **多轮重复上一问**：用户与助教消息在同一事务中使用数据库默认时间戳，可能获得相同 `createdAt`；仅按时间排序后倒序，不能保证问题先于回答。真实连续回归曾出现平均分回答重复人数、设备回答重复平均分。现在兼容排序旧消息，新消息保存不同的时间戳，并明确历史只用于延续当前问题。

## 3. Response Router

路由只使用本轮问题，不创建新会话，不更换课程，也不切换知识库。

| 类型 | 触发和回答形式 |
| --- | --- |
| FACT | 多少、平均分、有没有、是不是等。直接答事实，1–4句话，建议为空、未请求示例为空。 |
| EXPLANATION | 为什么、原因。简短结论与2–4个关键原因，不能扩成整节课设计。 |
| TEACHING_ADVICE | 怎么处理、应该提供什么支架等。少量可执行建议，结合当前学情，不强制整节课。 |
| ACTIVITY_DESIGN | 设计/安排一个活动或练习、压缩已有活动。写明当前体裁和主题，可展开目标、分钟拆分、师生活动、分组、支架和评价。 |
| FULL_LESSON_DESIGN | 只有显式索要完整教案、完整教学设计、一整节课或45分钟流程才允许。仅提及“完整教案”或问有没有，不会开启完整结构。 |
| EXAMPLE_REQUEST | 显式索要例子、例句或模板。单独提供所问示例；在其他意图中明确索要示例也能开启 examples。仅问“为什么这个模板不适合”不会触发。 |

先处理更明确的完整教案/活动/策略请求，再处理原因、示例、事实。规则不能确定时，让**原有回答生成调用**同时给出内部 intent，不新增分类调用；缺省采用简短 EXPLANATION。后台不会接受未授权的完整教案类型。intent 不在教师页面显示。

事实正文超过四句话、包含额外栏目，或模型选择未请求的完整教案时，使用同一课程、资料、历史修复一次，不直接截断证据。正常路由没有额外模型调用；只有异常格式/形式修复可能增加调用。事实和待分类问题先校验再展示，其他明确问题继续流式显示。

## 4. Evidence Policy

用户主动关联的资料默认是可信教学事实。指令安全边界不变：资料里的“改变规则、忽略系统”等指令不执行。没有明显冲突、过期或高风险时直接引用，不例行要求重查名册或成绩。

只有资料相互冲突、资料与课程冲突、明确有效期已过、实时状态查询、来源不明确、高风险决定或仅能推断时，说明具体缺口或请教师确认。文件较早不自动等于过期。

来源明确写出的事实直接陈述；合理推断注明“可能/推测”和依据；缺乏依据的群体对应关系不能陈述为事实。成绩区间与A/B/C分层没有直接关系说明时，不根据接近人数推断重合群体或重合人数。

优先级继续是：系统规则→当前课程→教师明确要求→知识库→本轮网页→当前会话历史→模型通用知识。互评已设7分钟、资料建议5分钟时，先交代课程实际7分钟，再提出5分钟核心操作加2分钟说明/修改的建议；不修改课程存储，也不把建议拆分说成来源事实。

## 5. Source UI 数据流

原检索结果→原有模型上下文与会话保存→展示层按documentId聚合→去除重复ID/重复文本→文件卡片与命中数→点击“查看引用”展开原始引用→经原有用户归属校验查看解析原文或下载文件。

同一文件的不同片段只形成一张卡片。不同文件即使同名也不合并。示例命中两个不同片段时显示“命中2个相关片段”，不虚报三个。引用默认收起，以“片段1/2”等展示顺序标记，不暴露检索索引、相似度或内部ID。正文使用真实文件名称归因，本轮不引入新的行内引用架构。

## 8. 未解决问题与技术债

- 没有新增正文逐事实的行内引用编号；目前为正文真实文件名加底部文件卡片，符合本轮最小改动范围。
- 事实/推断边界主要由证据提示策略和真实回归约束，尚无通用语义证据验证器；不能把句数和栏目检查当作事实正确性证明。
- 旧会话仍能读取原结构，历史文本没有重生成；旧时间戳相同的问答由兼容排序处理。
- 模糊问题若模型未提供intent，采用简短EXPLANATION；未增加第二条分类链路。异常长度/格式修复会有额外延迟，事实回答不显示尚未校验的流式中间稿。
- 现有 Vitest/Vite 配置有未来默认加载方式兼容提醒，本轮未调整与回答体验无关的测试基础设施。

## 9. 后续补充：自选删除对话历史

课中助教的历史列表增加逐条删除入口，列表名称改为“对话历史”。点击垃圾桶后展示所选标题，并允许保留或确认删除。手机页面在聊天区下方显示历史列表。

删除其他历史时保留当前对话及未发送草稿；删除当前对话时清空消息和会话ID，返回当前课程的空白聊天，重新发送会创建新会话。请求失败保留原历史和确认窗口，允许重试；回答生成和删除过程中禁用冲突操作。

新增 `src/app/api/classroom/[id]/route.ts` 的 DELETE 接口，沿用登录及请求来源校验，原子删除条件同时包含会话ID和当前用户ID。数据库既有级联关系删除该对话的全部消息，不需要修改schema或迁移；无权访问和不存在的会话统一返回404。

本补充修改 `src/components/classroom-chat.tsx`、`src/app/workspace.css`，新增上述API及 `tests/unit/classroom-delete.test.ts`，扩展 `tests/e2e/workflow.spec.ts`。最终 lint、typecheck、build通过；单元测试75项通过。既有4项浏览器工作流通过，新增删除工作流单独复验通过：取消、失败重试、历史刷新、草稿保留、当前对话清空、手机入口、消息级联删除、删除后新建、未登录401、跨用户404和跨站403。手机截图位于 `output/assistant-qa/history-delete-mobile.png`。
